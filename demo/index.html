Agent Exec Guard

A seccomp user-notify + Landlock execution policy layer for OpenHands AI agents. Every execve decision is explicit. The model cannot self-report past the kernel boundary.

The Problem

OpenHands executes arbitrary binaries inside its sandbox.

⚠ Unconstrained exec inside the container

Docker's default seccomp profile blocks ~44 dangerous syscalls but does not restrict execve. An AI agent that issues a bash command can run anything present in the container — including tools the operator never intended to allow. The model's self-reported behavior cannot be verified at the execution boundary.

Policy Workflow

Observe. Generate. Review. Enforce.

Sprint 10 closed the hardcoded-policy gap. Real guard audit logs from a live agent session drive automatic YAML policy generation. A human reviews before any enforcement.

👁
Observe
Run agent in guarded session. Every exec logged to audit stream.
⚙️
Generate
ALLOW records → reviewable YAML. BLOCK records preserved separately.
🔍
Review
Human approves proposed allowlist. Any ALLOW/BLOCK overlap excluded.
🔒
Enforce
Compiled JSON → guard. Anything outside policy blocked at exec time.
Comparison

Additive, not a replacement.

Docker seccomp (default)

Broad compatibility baseline. Blocks ~44 dangerous syscalls. Does not restrict execve to agent-specific policy.

gVisor / Firecracker

Stronger kernel isolation. Different deployment model. Does not provide per-agent executable identity policy.

E2B / bubblewrap

Sandboxed execution environments. No per-binary identity enforcement tied to the agent policy surface.

Agent Exec Guard (this lab)

Lightweight additive layer around existing OpenHands Docker runtime. Every execve decision is explicit, identity-verified, and audited. Works under default Docker seccomp, no CAP_SYS_ADMIN required.

Proof Chain

Ten sprints. Twenty-two independent audits.

SprintClaimResult

✓ Current Strongest Claim

On the prepared lab machine, a pinned OpenHands 1.6.0 headless CodeActAgent loop driven by OpenAI gpt-5.2 can issue real execute_bash tool calls through the OpenHands Docker runtime action server, while a seccomp user-notify plus Landlock guard wraps that action server, allows approved executable identities, blocks a copied /usr/bin/rm renamed to ./python3, and returns Operation not permitted through the OpenHands trajectory.

Real guard audit logs from a live run generate reviewable YAML policy, compile to guard JSON, and rerun the demo successfully under the generated policy while preserving the block assertion.

✗ Not Claimed

  • Production-grade sandbox security
  • Full OpenHands web UI or non-CmdRunAction coverage
  • Complete F_CONT TOCTOU closure
  • Read / write / network isolation
  • Automatic policy approval without human review
  • Signed or tamper-proof audit logs
